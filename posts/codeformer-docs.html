CodeFormer 深度盘点：从老照片修复到 AI 生图后处理，一个模型能扛多少活

下载 2026-10-16 ·约 8 分钟 ·老杨

CodeFormer 不是又一个"人脸修复工具"那么简单。它用 VQGAN Codebook 的离散建模思路，在保真度和修复力之间走出了一条跟 GFPGAN 完全不同的路。本文从能力域到适用场景做一次系统性的盘点。

如果你在找人脸修复工具，十有八九先碰到的是 GFPGAN——那个一键式、参数都不用调的 GAN 模型。但如果你手里的照片还能认出是谁、只是画质不好，GFPGAN 那套激进的恢复策略反而容易"修得不像本人"。CodeFormer 就是在这个细分缺口上被 NTU S-Lab 推出来的，去它的CodeFormer官网能看到完整的项目介绍：它用 VQGAN Codebook 的离散 token 建模思路，不去猜一张"应该长什么样的脸"，而是在大量人脸 token 的组合空间里找最匹配的那一组。

这条技术路线决定了 CodeFormer 的性格——保真度优先。w 权重越小它越愿意改脸（画面优先），w 越大越克制身份维度的改动（保真优先）。这个简单的滑块背后藏着一个完整的工具链：从老照片到 AI 生图、从整图到视频、从上色到划痕修复，CodeFormer 其实是一个多入口的人脸处理框架。下面按能力域逐个展开。

能力域一：人脸修复本体——w 权重背后的权衡艺术

CodeFormer 的核心推理脚本只有一个必填参数 -w，取值范围 0 到 1。这个权重控制的是 Codebook token 在解码时的"重建 vs 生成"倾向：

  • w 接近 0：模型更倾向于从训练分布里"采样"一个好看的脸，画面优先，代价是身份特征会被弱化
  • w 接近 1：模型严格按输入退化人脸的 token 序列重建，身份保真优先，代价是极端退化时可能"修不动"

实际使用中，w 的选择高度依赖场景：老照片修复用 0.6~0.8 保证不把长辈修成网红脸，AI 生图后处理用 0.2~0.4 因为反正不存在"保真"问题只需要看起来自然，视频逐帧增强用 1.0 避免同一人前后帧长得不一样。更多参数组合和边界情况可以去CodeFormer文档翻。

和 GFPGAN 的对比是绕不开的话题。简单说，CodeFormer 对还能认出是谁的中等退化最稳，GFPGAN 对连是谁都看不清的重度退化更有存在感——前者保守不瞎改，后者激进能救回来。两者互补而非替代，Replicate 上很多生产环境会同时跑两个模型做交叉验证。

能力域二：背景增强与整图修复——不只是修脸

CodeFormer 推理模型本身只处理人脸区域，头发边缘、肩膀、背景、衣服这些它完全不管。如果只跑基础命令，你会得到一张"人脸清晰、背景模糊"的照片，边界处甚至可能像贴上去的一样——这就是很多人第一次用 CodeFormer 觉得"假"的原因。

解决办法是 --bg_upsampler realesrgan。Real-ESRGAN 是腾讯 ARC Lab 开源的通用图像超分辨率模型，CodeFormer 作者把它作为默认的背景增强器挂到了推理管线里。加了这个参数后，处理流程变成两路并行：CodeFormer 修人脸 + Real-ESRGAN 增强整张图，然后把 CodeFormer 的修复脸贴到 Real-ESRGAN 的背景上，接缝用 back projection 融合。

代价也很实在：显存多吃 3.5GB，时间多花约 35%。8GB 显卡的用户大概率会在这里触发 OOM，只能放弃背景增强或者缩小输入图。12GB 显存是"整图 + 背景增强"的舒适起点。

能力域三：多场景入口——不是一个脚本包打天下

CodeFormer 的仓库里其实不止一个推理脚本：

inference_codeformer.py 是主入口，整图或裁切对齐的人脸都能处理。支持 --has_aligned 模式跳过 YOLOv5 人脸检测直接推理，省 1GB 显存，适合已经批量裁好对齐人脸的场景。

inference_colorization.py 是独立的黑白上色工具，只接受 512×512 裁切对齐的人脸，不上色背景。颜色风格来自 FFHQ 彩色数据集学到的"自然肤色"，不是写实还原——博物馆数字化场景用不了，但老照片头像翻新够用。

inference_inpainting.py 处理划痕、涂鸦、遮挡。用法很简单：在 Photoshop 或 GIMP 里用白色画笔涂掉要修复的区域，脚本会把白色当作 mask 只修复被遮住的部分。mask 不要超过人脸 30%，太大修复效果会明显下降。

视频逐帧增强没有独立脚本，而是在主入口上加 --input_path 指向视频文件，内部用 ffmpeg 做逐帧提取和合成。这里有两个注意点：一是 Windows 用户特别容易忘装 ffmpeg 且没配 PATH，二是 CodeFormer 是逐帧处理的没有显式时间约束，但 Codebook token 的确定性反而让同一人的相邻帧预测出相似的 token 序列，时间一致性比 GAN 方法好一些。

能力域四：工程化参数——让它在你的机器上跑起来

CodeFormer 的门槛不在效果而在"让它跑起来"。安装包从官方下载获取，几个高频踩坑点集中在：

显存分配：不开背景增强约 8.5GB，开了约 12GB。8GB 卡用户的组合拳是：关 --bg_upsampler（省 3.5GB）+ 用 --has_aligned 跳过检测（省 1GB）+ 图片先缩小再处理（面积减半激活值显存减 4 倍），三管齐下能把需求压到 5GB 以下。还可以加 --fp16 走混合精度，显存减半还更快。

ffmpeg 依赖：视频处理必须有。Windows 最推荐 Conda 环境内一条命令装好自动进 PATH；手动装的话解压路径别带空格和中文，改完 PATH 要重开终端窗口。VS Code 用户还要注意 Python 解释器和 Conda 环境的对应关系——GUI 启动的应用 PATH 可能不包含 ffmpeg。

云 GPU 平台：AutoDL、矩池云这类国内平台通常预装 ffmpeg，直接 ffmpeg -version 确认就行。Colab 里一行 !apt-get install ffmpeg 搞定。

短板也要说

CodeFormer 不是万能的。实时视频增强（30fps）单帧推理要 100~300ms，实时场景需要 <33ms/帧，差了一个数量级——有专门的轻量模型做这个事。完全糊成一团、连五官轮廓都看不清的照片，CodeFormer 不管 w 设多少都只能编一张"像样的脸"出来，不如 GFPGAN 编得好看。背景里有重要文字（证件照、文件扫描件）的时候不能开 Real-ESRGAN，它对低分辨率文字会"瞎猜"成乱码。

什么样的人该用它

手里有老照片想修复的家庭用户、AI 绘画玩家需要在 Stable Diffusion / Midjourney 生成后端接一个后处理节点的创作者、做视频逐帧增强的剪辑师——这三类人是 CodeFormer 最匹配的画像。第一类看重保真度不想把长辈修成网红脸，第二类追求画面自然度不在乎身份一致性，第三类需要 w=1.0 的时间稳定性保证同一人前后帧长得一样。

从一个简单的人脸修复模型出发，CodeFormer 实际上已经长成了一个覆盖修复、增强、上色、补全的小型工具生态。它不一定是效果最惊艳的那一个，但在"保真度可控"这个维度上，目前还没有开源方案能完全替代。如果你还没试过，可以先去官网拿安装包跑一跑。这份整理好的资料我在GitHub、Gitee和GitCode上各同步了一份，国内访问选 Gitee 或 GitCode 更稳。
