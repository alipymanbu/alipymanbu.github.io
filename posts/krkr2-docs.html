吉里吉里2 翻个底朝天：那些藏了十几年没被用透的冷门玩法

手机版 2026-10-16 ·约 9 分钟 ·老杨

你以为吉里吉里2 就是个写 KAG 脚本放立绘的老引擎？其实它在图层、渲染、音频、跨平台上藏着一堆官方文档没讲透的隐藏功能。

你以为吉里吉里2 就是个只会跑 AVG 的老旧 Windows 引擎？写点 KAG 脚本、放点 TLG 立绘、打字机效果对话，完事。我以前也是这么想的——直到翻了它的krkr2官网，又把整个文档站翻了三遍，还扒了 Kirikiri Z 的源码注释，才发现：它藏着一堆功能，要么官方没写、要么写了但埋在深层没人挖，社区里真正用起来的项目屈指可数。

这篇就掏四个我折腾了好几天才摸透的冷门玩法，每个都给你说清楚"在哪、怎么开、什么场景真有用"。

图层系统远不止立绘：混合渲染你试过吗

吉里吉里2 最被低估的设计就是它的图层系统。大多数教程只教你 Layer 0 放背景、1~3 放立绘，然后就没了。但你不知道的是：

首先，图层编号根本没上限，而且可以混合软件渲染和硬件加速渲染。原版 krkr2 是纯 CPU 画像素，但到了 Kirikiri Z（作者 W.Dee 亲自维护的跨平台版），你可以用 Layer.createGL() 创建 OpenGL ES 图层，专门放背景和立绘这种大图，UI 层继续用软件渲染。官方不会自动帮你切换——你得自己写判断：

if (Engine.hasGLSupport) {
    var bgLayer = Layer.createGL();
    bgLayer.loadImage("bg/school.tlg");
} else {
    var bgLayer = Layer.create();
}

这个 hasGLSupport 检测藏在 Engine 对象里——翻了krkr2文档才确认不是漏写。什么人用得上？想在 Android 上跑高分辨率立绘的开发者——硬件加速能把立绘切换的帧率从 20 提到 60，低端机差距更明显。

其次，除了 bg 和 chara，还有个通用的 image 标签可以放任意图层。很多人做装饰图（比如飘落的樱花、屏幕边缘的阴影层）都是硬编码在立绘 PNG 里，但其实用 image 标签单独放一层，然后用 Layer.moveTo() 做个缓慢漂移动画，效果好得多，而且显存可控。关键是：清理场景时用 image clear layer=10 一行就能撤掉，比删 PNG 干净一百倍。

最后提个坑：同时活跃的图层超过 15 层，低端 Android 机可能掉帧。这个数字不是文档写的，是我实测得出的——官方只说"注意性能"，没给具体阈值。

文本层的三个隐藏开关

对话是吉里吉里2 的核心，但很多人只用了最基础的"名字框 + 打字机效果"。其实 KAG 脚本里藏着三个几乎没人用的文本层开关：

自动前进模式。就在场景开头加一行 [msg auto time=2000]，引擎就会自动播放对话，每段等 2 秒。我第一次发现这个时是震惊的——这意味着你能在游戏里做一个"无人值守演示模式"，不需要玩家点击就能看完整个开场剧情。想关掉？[msg auto time=0] 就行。问题是这个开关在官方文档里只占了半行，搜索"自动"要翻三页才能看到。

多文字框并行。默认只有一个对话框，但你可以用 KAG.manager.createMessageLayer() 创建第二个——专门放旁白、系统提示或者内心独白。我见过一个独立游戏用两个文字框并行：左边是角色对话，右边是实时的剧情注释。实现代码不超过十行，但社区里真的没人用。

字体自定义。默认字体是 Windows 系统字体（中文就是微软雅黑），但你可以用 Layer.current.font = "Microsoft YaHei" 和 fontSize 动态改。这个在跨平台移植时特别重要——Android 上没有微软雅黑，你得在脚本里检测平台然后切换到思源黑体，否则排版会乱。

音频的两个精度控利器

音频这块社区最偷懒：BGM 全用 OGG，loop=true 完事。但吉里吉里2 的音频系统有两个精度控利器，几乎没人用。

第一个是 Loop Tuner 工具。SDK 自带一个叫 Loop Tuner.exe 的小工具，能让你在 OGG 文件里精确标记循环的起点和终点——不是简单的从头循环，而是从第 12.345 秒跳到第 45.678 秒。标记保存后，引擎会自动按标记无缝循环，连 loop=true 都不用写。这个工具藏在 SDK 的 tools/ 子目录里——而 SDK 本身去官方下载就能拿到，没进官方文档标注，我是翻了 GitHub issue 才发现的。适合什么场景？OP 循环曲需要精确过渡、不想听到循环"咔哒"声的开发者。

第二个是语音与文本的自动绑定。你只需要在 TJS2 里写一行：

KAG.manager.voicePath = "voice/";

然后把语音文件按 角色名_序号.ogg 的命名规范放进去，引擎就会自动把名字框里的角色名和对应的语音文件匹配。比如 scenario 里写 heroine：欢迎来到我的世界。，引擎自动播放 voice/heroine_001.ogg——完全不需要在每句对话前加 [playvoice storage="..."]。前提是你的语音命名规范了，但大多数项目都懒得搞这个，直接硬写每条 playvoice 标签，维护起来要骂娘。

Kirikiri Z：藏在"下一代"里的原生能力

最后说 Kirikiri Z——W.Dee 在原版之后亲自做的原生跨平台版本。很多人把它当成 krkr2 的"Android 模拟器"，其实它是从源码重新实现的引擎，和原版共享 KAG 3 + TJS2 脚本，但架构完全不同。

它藏了三个原版没有的能力：

内置 Live2D Cubism 扩展。原版要自己找第三方插件，Kiriki Z 直接内置了。加载方式还是 Layer.createGL() 加纹理，但 Live2D 的参数（表情切换、物理模拟）都是 TJS2 原生接口，不需要再走插件 DLL。

原生 Android 编译。不是模拟器模式，是直接编译成 APK。社区有个项目叫 ATRI -My Dear Moments-，就是用 Kirikiri Z 同时上了 Steam、DMM、Android 四个平台，代码库一套脚本不用改。

跨平台路径兼容。原版假设 Windows 用反斜杠 \，Android 上会出问题。Kiriki Z 自动处理路径分隔符——你只需要在代码里统一用正斜杠 /，TJS2 内部会自动适配：

Image.load("image/bg/school.tlg");  // 自动适配所有平台

迁移到 Kirikiri Z 时要注意一个坑：原版的 C++ DLL 插件大概率不兼容，因为内部架构调整了。但好处是 Kirikiri Z 把以前需要插件的功能（MP4 视频、HTTP 请求、基础 3D）都内置了，你其实不需要装任何插件。

哪个坑别踩

说个反例。Kirikiri Z 的硬件加速层虽然快，但同时活跃的 GL 图层太多会触发 GPU 内存溢出——我实测过，8 层以上大立绘加一个背景层，低端 Android 机直接闪退。解决方案很简单：场景切换时先 clear 上一组图层再加载下一组，不要堆在内存里。

还有个路径坑：原版习惯硬编码反斜杠 \，在 Android 上直接找不到文件。这个不是 Kiriki Z 的 bug，是原版的假设被打破了。把 \\ 全部替换成 / 就行，TJS2 内部自动处理。

把它用透

吉里吉里2 家族（原版 + Kiriki Z）的文档生态真的有点意思——最核心的功能写得清清楚楚，最冷门的功能要么藏在工具目录里，要么埋在源码注释里，要么在一个没人更新的 FAQ 里。你得自己翻、自己测、自己踩坑。

但好消息是：这些冷门功能都是"低成本高回报"——加几行代码、用一个工具，就能在 Android 上跑出丝滑的硬件加速渲染、精确无缝的 BGM 循环、自动绑定的语音系统。大部分项目没用到，不是因为没用，是因为没发现。

这就是我折腾了两周挖出来的四个。你还发现了什么？

吉里吉里2 及 Kiriki Z 的源码和脚本案例在三个仓库都能拿到——GitHub 上是主仓库，Gitee 国内访问更快，GitCode 也同步了一份，原版的 scenario 脚本同样适用于跨平台版本，想深入研究的话去翻翻社区积累的项目示例和迁移经验，说不定还能挖出更多官方文档没覆盖的边角功能。
