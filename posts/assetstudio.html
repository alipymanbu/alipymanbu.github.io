AssetStudio 用了两年：从"提个 BGM 当铃声"到每天都开的工具

中文版 2026-10-16 ·约 10 分钟 ·老杨

从原版到 AssetStudioMod，从只会点 GUI 到能跑 CLI 批量导出，两年时间把 AssetStudio 的边界摸了个遍——有些预期高估了，有些功能越用越离不开。

AssetStudio 装到现在快两年了，它的官网我收藏了快两年。从 Perfare 原版 v0.16.47 用到现在的 AssetStudioMod .NET 9，中间踩过的坑比看过的教程还多——每个版本都是从官方下载拿的安装包。当初装它的理由特别朴素——某款独立游戏的 BGM 太好听，想提出来当手机铃声。就这么一个简单到有点无聊的需求，把我带进了 Unity 资源提取这个小圈子。

变化三连：哪些越用越顺，哪些慢慢露出了真面目

当初刚装上的时候，只觉得这东西"能开就行"。现在回头看，好几个点是用了一段时间才发现它真的设计得好——或者真的设计得坑。

Extract 再 Load，这个流程是我踩了三次崩溃才记住的。 第一次加载一个 300MB 的 AssetBundle，电脑风扇突然拉满，内存占用直顶 95%，窗口直接变灰被系统杀进程。我以为是包坏了，重新下载了三遍，结果每次一样。后来去assetstudio文档翻了一下才知道：AssetStudio 加载 AssetBundle 时是在内存里整包解压的，包一大内存峰值直接炸。

正确做法是先 Extract 到本地目录，再用 Load folder 扫解压后的文件。解压后的文件就是普通文件了，读取不再整包占内存，多大的包都能稳住。就这一个操作习惯的改变，让 AssetStudio 的可用性翻了倍。现在拿到任何 Unity 包，第一反应就是先 Extract——成了肌肉记忆。

Filter Type + 搜索框的组合，是我每天都在用的功能。 刚开始只会在 Asset List 里瞎翻，几百上千条资源里找一个音频或贴图，纯靠肉眼。后来发现列表区域右键有 Filter Type，可以按类型只勾选 AudioClip、Texture2D、Font 之类的——一下子把噪音砍掉大半。再加上顶部搜索框输个 bgm 或 icon，Include 模式自动过滤，定位一个资源从原来的十几分钟变成几秒。

AssetStudioMod 还加了正则模式，RegexName 和 RegexContainer 两种都支持。这个功能我用到的场合不多，但偶尔遇到一批命名不规范的资源时，一条正则就能把目标全部捞出来，省不少事。说个反直觉的：正则筛选我只用过不超过十次，但每次用都觉得"这功能设计得真好"——平时不显山露水，关键时刻救场。

CLI 是我当初完全没料到会重度依赖的东西。 刚上手时觉得 GUI 够了，点一点看预览再导出，体验挺直观。直到有一次需要从十几个散落在不同子目录的 AssetBundle 里批量导出所有 Texture2D——如果用 GUI，就得逐个 Load、逐个 Filter、逐个 Export，点到手酸。那时候才发现 AssetStudioMod 带了跨平台 CLI：AssetStudioModCLI，Windows、Linux、macOS 都能跑，-m info / export / dump / live2d / splitObjects / animator 切换模式。

一行命令就能搞定的事：AssetStudioModCLI -m export -i <输入目录> -o <输出目录> --filter-by-type Texture2D。现在但凡涉及批量处理、或者想写进脚本流水线，全走 CLI。GUI 留给临时看一眼、预览确认内容的场景——两个模式各有各的位置，谁也替代不了谁。

那些越用越烦的点：AssetStudio 也有它的边界

用了两年，也慢慢摸清了 AssetStudio 哪些事情它就是做不到。当初以为它"万能"，现在知道这些边界是工具本身的定位决定的。

UnityCN 加密包是硬伤。 大陆版 Unity 在 AssetBundle 里加了资源加密，原版和 AssetStudioMod 都打不开。Mod 版最多能检测到加密然后弹个提示，不会告诉你怎么解密。第一次遇到这种包时我以为是加载姿势不对，反复 Load、Extract、换版本，折腾了快一小时才放弃。后来才知道得用专门对付加密包的工具——Razmoth Studio 或 AnimeStudio。AssetStudio 在这块就是无能为力，不是配置问题也不是我菜。

MonoBehaviour 提取的门槛比想象中高。 想把 Unity 脚本组件里的字段数据导出来，AssetStudio 需要对应的程序集 dll。Mono 打包的游戏还好，直接喂 Managed 目录就行；Il2Cpp 打包的游戏就麻烦了，得先跑 Il2CppDumper 生成 dummy dll，再把 dummy dll 的目录喂过去。这个流程每次走起来都觉得繁琐——特别是某些游戏的 Il2Cpp 版本比较新，Dumper 还不一定能直接用。不是 AssetStudio 的锅，是 Unity 本身的技术路线决定的，但用起来就是烦。

Shader 在 Unity 2022+ 基本导不出东西。 Unity 2021 及更早的 Shader 资源包含可读的 HLSL/ShaderLab 源码，AssetStudio 能显示源码并导出。但 2022 之后 ShaderGraph 产生的 Shader 经过编译，不再包含可读源码。Asset List 里能看到 Shader 条目，但导出来是空的或者只有编译后的字节码。想研究 Shader 的话，还得去找 Unity 5.x 或 2020.x 的老项目。

观感修正：哪些当初的判断被时间打脸了

高估了原版的"官方感"。 刚开始装的是 Perfare 原版，觉得"原版就是正统"，Mod 版是"第三方"不放心。实际上原版 v0.16.47 之后就收官了，Unity 2023、2024、Unity 6 的数据格式变化原版根本跟不上。现在谁还在用原版？新项目一律选 AssetStudioMod。原版剩下的唯一价值可能是做个参考实现——如果你要自己改 C# 源码从官方基线 fork，再考虑它。

低估了社区生态的活力。 原版停更之后，我以为 AssetStudio 这个工具也就到头了。结果社区 fork 比原版还热闹——AssetStudioMod 活跃更新到 Unity 6000.2，加了 Live2D Cubism 导出、WebP、Switch swizzle 纹理还原、Dark Mode；SiMaLaoShi 专门适配国内团结引擎；甚至还有 ARM 64 架构的手机版。一个开源工具在作者停更后还能靠社区续好几年命，这种事在独立工具圈不算常见。

低估了 Extract 这一步的重要性。 上面提过了，但值得再说一遍：这不是一个"可选的优化步骤"，是处理大包的必须步骤。当初把它当成"内存不够时的备选方案"，现在知道它是 AssetStudio 使用的基本姿势。

哪些功能我碰都没再碰

说几个装了但几乎没用过的功能吧。

手机版 coyamo.assetstudio 我试过三次，每次都是"临时想在手机上看个包"，结果要么包太大手机 RAM 顶不住被杀进程，要么功能被砍了一大半（没有正则筛选、没有 CLI、Il2Cpp 游戏跑不了），最后还是传回电脑用 AssetStudioMod。手机版安装包 6.28MB 确实小，但能做的事情也确实少。现在我只在确实没电脑、文件又就在手机里的时候才会想起它——但这种场景一年到头也没几次。

Scene Hierarchy 标签页 我用得也不多。它按 GameObject 父子关系组织树形结构，在游戏 Mod 制作时找场景里的具体对象很方便。但我大部分时候是找贴图、音频、字体这些零散资源，Asset List 扁平列表 + Filter Type 筛选更快。Scene Hierarchy 留给 Mod 制作者吧。

VideoClip/MovieTexture 导出 只在早期用过一次。导出来就是原视频文件流，不解码不转码——能用，但我也没什么从 Unity 包里提视频的刚需。

去留结论：什么时候该换，什么时候继续用

AssetStudio 我不会卸载。它不是那种"用完就丢"的工具，而是你手头有 Unity 资源包时第一个会想到的东西。从原版到 Mod 版的迁移过程很平滑，CLI 加 GUI 的双模式已经成了我的工作流标配。

什么信号出现就该换了？说实话，暂时看不到。除非 Unity 出了下一代引擎格式把现有资源结构全推翻了，或者社区 fork 都停更了——后者可能性不大，前者如果真发生了那整个生态都得跟着变。

倒是可以多留意几个备选：如果遇到 UnityCN 加密包，Razmoth Studio 和 AnimeStudio 是现成的替代；如果目标是团结引擎的国产游戏，SiMaLaoShi 的 fork 专门适配过。但这些都是特定场景的补充，不是 AssetStudio 的替代品。

总结一下？两年用下来，AssetStudio 给我的感觉是：边界清晰，定位精准，社区撑住了后劲。 它不万能（谁也别想从 UnityCN 加密包里白嫖），但在它能覆盖的范围内，没有比它更好用的了。

这套资料在GitHub、Gitee、GitCode三个仓库都能拿到，随时可以去翻。
