把 After Effects 动画直接搬到 App 和网页？我试了 Lottie 一周

官方版 2026-10-16 ·约 8 分钟 ·老杨

前端和移动端开发绕不开的动效方案，设计师用 AE 导出 JSON，开发者嵌入 SDK 就能播。上手实测它的安装、嵌入和跨平台体验，聊聊好在哪、坑在哪。

为什么我会去装 Lottie

事情起因挺简单的：上周产品经理甩过来一个需求，App 首页加载态要换个「有点质感」的动画。之前用的 GIF 动图体积大不说，在不同分辨率的手机上还经常糊成一团。我本来打算自己用 CSS 重写一个 loading，结果去设计那边拿素材的时候，发现他们已经在用 After Effects 做好了一套动画，而且导出了 Lottie 格式的 JSON 文件。

说实话我之前对 Lottie 的认知停留在「设计师导 JSON，开发嵌入就行」这个层面——听起来像是个零成本的东西。实际跑了一圈才发现，它确实把设计端和开发端之间那条最头疼的交付缝给填上了，但也不是说拿过来就能无缝跑。Lottie 是什么？简单说就是 Airbnb 开源的一套跨平台动画方案，设计端用 AE 加 Bodymovin 插件导出 JSON，开发端在 Web、Android、iOS、Flutter 等各个平台引入 SDK 就能播放。它的官网目前被国内墙得厉害，想直接访问得挂梯子，这点挺闹心的。

第一眼：嵌入比想象中简单

我先从 Web 端试起的，毕竟改个 HTML 文件就能跑，不用装 IDE。官方的 Web SDK 叫 lottie-web，CDN 直接引一行 <script> 就行，然后页面上放个空的 div 容器，一段 JS 调用 lottie.loadAnimation() 就搞定了。

lottie.loadAnimation({
  container: document.getElementById('lottie-container'),
  renderer: 'svg',
  loop: true,
  autoplay: true,
  path: 'loading.json',
});

整个过程不到十分钟，动画就在浏览器里转起来了。说实话这是我没想到的——之前写 CSS keyframe 动画，调位置、调缓动、调循环，一个 loading 折腾半小时都正常。现在一个 JSON 文件解决了。

不过这里有个小坑：容器必须设明确的宽高，动画会填满容器。我一开始忘了给 div 加样式，结果动画直接缩成一个小点。还有两个参数值得留意——renderer 选 svg 还是 canvas，以及 JSON 是用 path 外部加载还是 animationData 内联。我的经验是，简单动效用 SVG 渲染、小文件直接内联，省一个请求；复杂动效或者需要远程更新的，走外部 JSON + CDN 托管更灵活。

iOS 和 Android 也想跑？各有各的脾气

Web 端跑通之后，我又去 iOS 项目里试了下。从下载拿到 SDK 之后，lottie-ios 支持 iOS 11 以上，安装方式有 SPM、CocoaPods、Carthage 三种。我用的是 Swift Package Manager，Xcode 里 File → Add Packages... 加一下仓库地址就完了。这里有个细节要注意，Lottie 团队现在推荐用一个叫 lottie-spm 的瘦身仓库而不是主仓库——主仓库体积超过 300MB，SPM 每次拉取会非常慢，瘦身仓库只有几百 KB，是预编译好的 XCFramework。

Android 那边用的是 lottie-android，Gradle 里加个依赖就能用。不过我没实际在 Android Studio 里跑完整流程，就不多说了——两边的 API 命名和参数各有各的风格，但核心思路和 Web 端一致：创建容器 View，设置动画文件，然后播放。

让我印象最深的是跨平台一致性。同一份 JSON 文件，我在 Chrome、Safari、iPhone 真机、Android 模拟器上都跑了一遍，视觉效果几乎一模一样。这在之前用 PNG 序列帧或者 GIF 的时候是根本不敢想的——每个平台的像素密度、渲染引擎都不一样，出来的效果参差不齐。

不想把 JSON 打包进 App？CDN 托管解决

第二个让我挺惊喜的功能是 LottieFiles 的 CDN 托管。动效 JSON 虽然小，一般几十 KB 撑死了，但如果每个运营活动都加一个、每个节日主题都加一个，攒起来 APK/IPA 的体积还是会蹭蹭涨。而且更麻烦的是，打包进 App 的动效要更新就得重新发版。

LottieFiles 提供了文件托管和全球 CDN 加速——你把 JSON 上传上去，它给你一个永久的 CDN URL，各平台 SDK 通过 URL 远程加载就行。Web 端直接把 path 参数换成 CDN 地址，iOS 用 animationView.load(url:)，Android 用 setAnimationFromUrl()，几行代码的事。

这里有个我觉得挺合理的建议：常驻功能的核心动效（比如品牌 Logo 动画）打包进本地资源，保证首屏不闪；运营活动、节日主题这些临时性的动效走 CDN，随时可以换。我按这个策略改了一下首页的加载动画，上线后运营那边说效果不错，而且后面想改动画内容也不用我重新发版了。更多远程加载和托管的进阶玩法，在Lottie文档里写得挺详细的。

和 GIF、CSS、AVD 对比一下

试了这几天之后，我也忍不住跟之前用过的方案比了比。

GIF 动图体积大（一段 5 秒的动效通常 500KB 起步）、最多 256 色、不能缩放、没有交互——基本是表情包和社交平台小动图的专属了。PNG 序列帧质量好但体积是 Lottie JSON 的 30 到 50 倍，适合那种矢量表达不了的逐帧手绘动画。CSS 动画在纯 Web 端做简单 loading 和 hover 动效其实挺不错，零依赖，但复杂动效写 keyframe 会很痛苦，而且 Android/iOS 原生不支持。Android 自己的 AVD 在纯 Android 项目里表现优秀，但只能 Android 用。

综合下来，Lottie 在跨平台品牌动效、引导动画、状态切换这些场景里几乎是最好的选择——矢量可缩放、JSON 体积小、设计到开发一条链到底、API 能控制播放暂停跳转、还能远程热更新。当然也有边界：复杂的 AE 表达式需要预烘焙，3D 层不支持，SDK 本身也要引入（Web 端 gzip 后约 40KB）。

适合谁，不适合谁

如果你是前端或移动端开发，项目里需要跨平台一致的动效，而且设计师用 After Effects 做东西——Lottie 基本上是必学的。它解决了一个长期存在的痛点：设计端的动画之前只能导出 GIF 或视频，糊、大、没法交互；现在直接导出 JSON，各平台原生渲染，效果对得上，开发量还小。

如果你的动效需求很简单，就是一个网页的 loading spinner 或者按钮 hover 效果，那用 CSS/SVG 动画更轻——毕竟引入 Lottie SDK 也有成本。社交平台的表情包场景 Lottie 也进不去，那是 GIF 的地盘。还有那种超复杂的逐帧手绘动画，矢量格式表达不了，得用 PNG 序列帧。

写在最后

Lottie 不是万能的，但它确实把设计师和开发者之间的协作效率拉高了一大截。我这一周从安装到嵌入到跨平台测试，整体体验比预想中顺畅，踩的几个小坑也都是文档里说过的——只要照着做就不会翻车。

这套 Lottie 相关的资料我在GitHub、Gitee、GitCode 三个仓库都同步了一份，方便不同网络环境下访问。海外网络优先 GitHub，国内访问选 Gitee，GitCode 那边也放了一份作为备份兜底。三个仓库的内容完全一致，选哪个都行。
