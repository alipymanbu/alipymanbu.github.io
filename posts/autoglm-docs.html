AutoGLM 深度盘点：让大模型真正会用手机的开源框架到底能做什么

手机版 2026-10-16 ·约 8 分钟 ·老杨

从视觉理解屏幕到跨 App 自动执行，AutoGLM 把 Phone Use 能力做成了可落地的工程框架。这篇盘点把它的能力面、适用场景和局限一次说清。

大语言模型能写代码、能做问答、能生成内容，但它们始终停留在桌面键盘的这一侧。现实里大量高价值操作发生在手机的图形界面上——点按钮、输文字、翻页面、选位置——这些动作靠传统脚本录制易脆，靠 App 内部 API 拿不到，而且每个 App 各一套。智谱 AI 在 2025 年 12 月开源的 AutoGLM 就是奔着这个缺口来的，它不是一个单点工具，而是一套完整的手机 Agent 工程框架，官网上能看到完整的交付物清单。

这篇文章会把 AutoGLM 的能力面完整铺开。我会按能力域分组盘点它解决问题的维度，客观讲它的亮点、适用场景和短板，最后给一张什么样的人该用它的画像。

能力域一：视觉驱动，不依赖 App API

AutoGLM 的核心思路和传统 UI 自动化工具完全不同。它不解析 App 的组件树（像 Appium 那样），也不预录脚本回放固定坐标（像按键精灵那样），而是真正"看着"屏幕想步骤、动手做。整个链路是：截图 → 视觉语言模型理解当前画面 → 生成下一步点击坐标 → 通过 ADB/HDC 执行动作。

这个设计的直接好处是跨 App 通用性。AutoGLM 内置的应用映射表已经覆盖了 50 多款主流中文 App——微信、QQ、淘宝、京东、美团、饿了么、携程、bilibili、抖音、小红书、知乎……从社交通讯到电商购物，从美食外卖到出行旅游，从视频娱乐到内容社区，每个分类都有典型代表。你跟 Agent 说话时直接用中文 App 名就行，比如"打开美团搜索附近的火锅店"，框架内部会自动把"美团"翻译成 Android 包名 com.sankuai.meituan，不需要你记任何技术细节。

如果某个 App 没在清单里也不怕，手动加一行映射就行——找到包名（adb shell pm list packages | findstr 关键词），在 apps.py 里追加一行中文名到包名的对应关系，同时在 System Prompt 里告诉模型这个新 App 存在，就搞定了。

能力域二：多端覆盖，不止 Android

AutoGLM 交付时不只是 Android 一家。框架的设备控制适配层同时支持三条通路：ADB（Android）、HDC（HarmonyOS NEXT）、WebDriverAgent（iOS）。鸿蒙侧已验证覆盖 60 多款应用，而且鸿蒙有一个 Android 没有的优势——重启后无线调试不会被重置。Android 设备重启后 TCP/IP 模式默认关闭（Google 的安全设计），每次都要插 USB 重新 adb tcpip 5555，鸿蒙不需要这步。

模型层面也分两个版本，下载页面可以拿到完整的权重文件：中文版的 AutoGLM-Phone-9B 针对中文 App 场景优化，多语言版的 AutoGLM-Phone-9B-Multilingual 支持英文 App（Gmail、Google Maps、X 等）。启动 Agent 时加 --lang en 就能切英文 System Prompt。

能力域三：远程无线调试，摆脱 USB 线

线连是最稳定的方案，但拖着一根 USB 线确实碍手。AutoGLM 支持 ADB WiFi 无线控制，配置好之后电脑和手机在同一 WiFi 下就能直接操作。

无线调试的门槛不算高：手机上先用 USB 插一次跑 adb tcpip 5555 开启 TCP/IP 模式，然后 adb connect 手机IP:5555 就能连上。但实际使用中坑不少——跨网段肯定连不上，企业网络通常有 AP 隔离导致设备之间互相看不到，手机切 WiFi 后 IP 变了也要重新连。AutoGLM文档专门给了一份排查手册，从 connection refused 到连接频繁断开，每条现象都列了逐项排查流程，甚至附了一张排查流程图。

能力域四：双集成方式，开发者友好

如果你只是想跑起来看效果，直接用 CLI 就行——命令行敲自然语言指令，框架驱动手机完成操作。如果你想嵌入自己的项目，Python API 提供了完整的 Agent 主循环接口，截图、理解、规划、执行每一步都可以单独调用和调试。

这套框架从 2023 年 4 月项目启动到 2025 年 12 月开源，中间踩过的坑全部放进了这份工程交付物里。GitHub Star 在开源 24 小时内突破 1.7K，社区反应挺快。

短板也要说

盘点不能只说亮点。AutoGLM 的局限同样明确：

感知延迟是硬伤。视觉模型理解屏幕画面需要时间，整个链路（截图 → 理解 → 规划 → 执行）的延迟比 Appium 这种直接解析组件树的方案高不少。对实时性要求高的场景它就不合适。

环境配置有门槛。ADB 的安装、PATH 环境变量配置、手机端开发者模式和 USB 调试的开启、数据线要支持数据传输——这一连串步骤对新手来说容易卡壳。文档里专门给了 ADB 安装的完整指南，Windows/macOS/Linux 三端都覆盖，但跑不通时的排查还是要费点时间。

无线调试稳定性依赖网络环境。WiFi 信号弱、手机离路由器远、穿墙多都会导致连接断开。省电模式也可能在信号弱时自动关掉无线调试。企业网络的 AP 隔离几乎是无解的——要么用手机热点让电脑和手机连同一热点，要么换回有线 USB。

手机重启后无线失效（Android）。这是 Google 的安全设计，防止恶意应用滥用无线调试。每次重启都要插 USB 重新跑一次 adb tcpip 5555。

什么样的人该用它

个人自动化爱好者——如果你想让手机帮你做那些重复性的 App 操作，比如每天定时打开某个 App 看数据、自动抢票、自动签到，AutoGLM 的跨 App 通用性比你自己写脚本省事太多。而且开源 + 私有化部署意味着数据和控制权全在你自己手里，不用担心隐私问题。

开发者和测试工程师——传统 UI 自动化工具（Appium、UIAutomator）每个 App 各一套适配，换框架就得重写。AutoGLM 用视觉理解绕过了这个问题，不知道目标 App 内部组件结构时它照样能跑。适合做跨 App 的流程测试、回归测试。

AI 研究者——从 2023 年项目启动到开源，AutoGLM 团队还发表了 ComputerRL、MobileRL、AgentRL 三篇强化学习论文，验证了强化学习在 Phone Use 场景的规模扩展定律。模型权重 MIT License、代码框架 Apache-2.0，最宽松的开源许可给足了研究空间。

这套资料在三个仓库都能拿到，国内访问看 Gitee 更顺畅，GitCode 作为备份源，GitHub 上有完整的提交历史和 issue 讨论。
