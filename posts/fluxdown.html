FluxDown 从零上手实战：浏览器下载、流媒体抓取、断点续传一条龙搞定

网页版 2026-10-16 ·约 10 分钟 ·老杨

下载管理器不止是多线程拉文件——FluxDown 把浏览器接管、剪贴板监听、HLS/DASH 解密合并、SQLite 断点续传揉进了一套本地优先的引擎里。这篇教程带你从零把主流下载场景跑通。

FluxDown官网 是一个本地优先的下载管理器——你可能之前用过 IDM、Motrix、aria2，那 FluxDown 跟它们最大的不同在于，它把浏览器扩展、剪贴板监听、自定义 URL 协议、本地 HTTP API 四条输入通道汇聚到同一套引擎上，下载任务统一进 SQLite 持久化队列，断电不丢进度、重启不丢状态。这篇教程结束时，你能从零完成：浏览器里拦截下载、从流媒体站点抓 HLS/DASH 视频、剪贴板复制 URL 自动入队，以及理解它为什么比传统下载器更稳。

准备：版本、平台与前置条件

FluxDown 支持 Windows（安装版 / 便携版）、macOS、Linux（AppImage / deb / rpm）和 Android（引擎桥）。这篇教程以 Windows 便携版为例——解压即用，不用写注册表，干净。

前置条件只有一个：确保系统里没有被其他下载器抢先注册 magnet: 或 ed2k:// 协议（迅雷、Motrix 都可能占）。如果之前装过，先在卸载程序里清干净，或者到系统设置里手动把这些协议的默认应用还原。

第一步：安装与 Agent 常驻

下载 安装包后解压到任意目录（比如 D:\tools\fluxdown），双击 FluxDown.exe 启动。第一次启动会做两件事：弹出欢迎向导、在系统托盘注册一个 Agent 常驻进程。

Agent 层是 FluxDown 能脱离扩展单独工作的关键——它负责监听剪贴板、注册 fluxdown:// 协议、启动本地 HTTP API（端口 17800）。向导里问「是否开机自启」，建议选是，否则剪贴板监听和协议处理在你没开 FluxDown 时都不会响应。

安装完成后别急着关——主界面会显示一个空队列。点右上角「扩展」标签，记下里面的扩展下载链接，下一步要用。

第二步：浏览器扩展对接，基本下载流

FluxDown 的浏览器扩展支持 Chromium 全系列（Chrome、Edge、Brave、Arc）和 Firefox。以 Edge 为例：

  1. 打开 edge://extensions/，开启「开发人员模式」。
  2. 点「加载解压缩的扩展」，选择 FluxDown 安装目录里的 extension\edge 子目录。
  3. 扩展加载后，浏览器右上角工具栏会出现 FluxDown 的图标。

扩展装好后就可以试了：找一个任意文件下载链接（比如 GitHub Releases 上的 zip），右键菜单里会多一条「用 FluxDown 下载」。点一下，FluxDown 主窗口会弹出「新建下载」对话框，URL、文件名、保存目录自动填好，线程数默认 8。

确认点「开始」，你会看到任务进入队列、分段并行拉取、速度条跳起来。这就是 FluxDown 最基本的下载流——扩展只负责嗅探 URL 和携带 Cookie/Referer，真正拉数据的是本机引擎，中间不经过任何云端。

第三步：HLS/DASH 流媒体下载实战

这是 FluxDown 比传统下载器强得多的场景。大部分视频站点（B站、YouTube、流媒体直播平台）用 HLS（.m3u8）或 DASH（.mpd）格式分发视频——把一个完整视频切成几十上百个小片段，边下边播。传统下载器遇到这种清单文件只会下载一份空白 playlist，FluxDown 能读懂清单、并行拉分片、自动解密、合并成完整文件。

从浏览器里嗅探出来

大部分情况下你不需要手动找 .m3u8 地址——扩展的媒体嗅探器会在你打开视频页面时自动识别当前页的视频流，图标变绿就是嗅探到了。点击扩展图标弹出的面板里会列出所有发现的流，点「送入 FluxDown」就完成了。

选画质、解密、合并

HLS 主清单通常提供多档比特率（比如 1080p 60fps / 1080p 30fps / 720p / 480p）。FluxDown 在下载前弹出选择对话框，每个选项标注带宽和分辨率。跳过（后台下发的任务）则默认选最高带宽档。

很多 HLS 分片用 AES-128-CBC 加密。FluxDown 自动从清单引用的位置拉取解密密钥、缓存后对每个分片边拉边解密——你看不到解密过程，最终拿到的是可直接播放的完整文件。Cookie 只会透传给与清单同源的分片和密钥请求，不会跨源发送到别的 CDN host。

DASH 的情况稍有不同：它常把音频和视频分成两个独立的 Representation。FluxDown 分别拉完后，如果系统里有 ffmpeg，自动做 stream copy 合并（不重编码，几秒钟完成）；如果没有，音视频各留一个文件（比如 video.mp4 + video.audio.m4a），需要你自己合并。

受管组件一键搞定 ffmpeg

不想自己装 ffmpeg？FluxDown 有「受管组件」功能——在设置 → 组件里一键让 FluxDown 自动下载 ffmpeg 和 yt-dlp，安装在自己的受控目录里，不污染系统 PATH。装好之后 DASH 合并就全自动了，HLS 和 yt-dlp 相关的高级抓取也能用上。关于 HLS/DASH 支持的完整参数和不支持场景清单，详见 fluxdown文档。

第四步：剪贴板监听和 fluxdown:// 协议

FluxDown 有三条不依赖浏览器扩展的输入通道——这是它和只做浏览器内拦截的扩展型下载器的核心区别。

剪贴板监听

Agent 常驻时自动监听系统剪贴板。你复制任意一种链接，FluxDown 都会弹出「新建下载」窗口，URL 自动填好：

  • http:// / https:// / ftp:// 开头 → 识别为普通文件
  • magnet:?xt=... → 识别为 BT 磁力
  • ed2k://|file|... → 识别为电驴链接
  • .m3u8 / .mpd 结尾 → 识别为流媒体

这个行为可以关掉（设置 → 浏览器 → 剪贴板监听）。不想被频繁弹窗打扰时关掉，但扩展仍然正常工作——剪贴板监听只是额外通道。

fluxdown:// 自定义 URL 协议

FluxDown 启动时自动注册 fluxdown:// 协议——和 mailto:、magnet: 一样是操作系统级的。任何应用、浏览器、IM、邮件客户端、命令行脚本都可以用这个协议拉起 FluxDown：

fluxdown://add?url=https://example.com/file.zip
fluxdown://add?url=magnet:?xt=urn:btih:...

FluxDown 没开时点 fluxdown:// 链接会先启动 FluxDown 再处理。这个协议特别适合 userscript、第三方下载按钮、自动化脚本使用——比调本地 HTTP API 简单。

常见卡点

AES-128 解密失败

如果 HLS 分片加密但 FluxDown 拉不到解密密钥，任务会标失败。常见原因是密钥 URL 在另一个域，Cookie 没透过去。解法：检查扩展是否在该页面激活、源站是否需要登录态才能拿到密钥。FluxDown 会从浏览器扩展里自动带 Cookie，但仅限同源。

DASH 下音视频各留一个文件

这是系统没装 ffmpeg 的表现。FluxDown 不会报错，只是不做合并。最快的解法是去设置里开启受管组件，一键让 FluxDown 自己装 ffmpeg——比你手动下载解压省事儿。

剪贴板监听太吵

复制任何 URL 都弹下载窗口确实烦。关掉它（设置 → 浏览器 → 剪贴板监听 → 关闭），扩展内拦截、fluxdown:// 协议、本地 HTTP API 都还正常工作，不影响主要使用场景。

进阶：本地 HTTP API

FluxDown 在本机默认监听 http://127.0.0.1:17800/api/v1/tasks，接受标准 JSON-RPC 请求。Tampermonkey userscript、自己写的 Python 脚本、甚至另一台机器上的 aria2 都可以直接调这个 API 给 FluxDown 下发任务。默认只绑定 localhost，要开 LAN 访问需要手动在设置 → 本地服务器里开启。这是把 FluxDown 集成到你自己的工作流里的最灵活方式。

FluxDown 的主仓库（引擎、daemon、agent、桌面端、CLI、Android 引擎桥）全部开源（AGPL-3.0）——源码同时托管在 GitHub、Gitee、GitCode 三个平台方便不同网络环境的访问，下载 URL 永远不上传服务器、匿名统计可完全关闭、云同步只同步设置不同步下载内容。如果你之前对下载器的印象还停留在浏览器弹窗扩展，值得换个角度看看这套本地优先的引擎设计。
