用了八个月 Novella，我对开源阅读器的几个真实感受

软件下载 2026-10-16 ·约 8 分钟 ·老杨

从当初为了摆脱闭源书架的广告推送，到现在每天睡前都在打开它，这八个月里对它的预期变了不少——有些功能越用越顺手，有些问题慢慢暴露，还有几个当初没在意的设计如今成了离不开的依赖。

去年春天换手机的时候把所有预装应用都清理了一遍，原本用的那款老牌阅读 App 也在卸载名单里——不是它不好用，是它最近几个版本开始在首页塞广告位，还时不时弹个会员续费提醒。在它的官网上简单看了下介绍后装的，抱着试试看的心态，毕竟开源阅读器在书架生态里算不上什么新东西。

八个月过去，我对它的感受已经从"试试"变成了"每天都开"。这种变化不是发生在第一次启动的时候，而是时间磨出来的。有些当初觉得别扭的地方越用越顺手，有些当初没在意的细节后来成了每天依赖的习惯，还有几个我一开始高估了的功能，实际体验并没有想象中那么好。

插件仓库：从"太麻烦"到"这才对"

刚装上 Novella 最懵的是它默认没有任何书源。之前用过的阅读器，打开就有一长串书源列表等着选。Novella 的设置页里只有一个空荡荡的插件管理入口，你得自己找插件仓库 URL 加进去，再从仓库里挑书源安装。后来去Novella文档翻了一下才弄明白，这是它的安全设计——让每个用户自己决定信任哪些来源。

说实话第一次用的时候我还真有点不耐烦——一个阅读器，打开不能直接搜书，还得让我折腾什么仓库管理？但这八个月用下来，我反倒觉得这个设计是它最聪明的地方。

Novella 把书源做成了 Lua 插件，每个书源是一个独立脚本，维护者可以独立更新。仓库更新默认每天检查一次，有新版本会通知你。我加了两个社区推荐的仓库，一个 LNReader 官方维护的，更新最及时；一个第三方的，有几本小众资源。后来有个第三方仓库停更了，我直接从插件页面长按移除，它下面的书源插件也一起卸掉了——但已经下载到本地的章节还在，只是这本书以后更新不会自动拉取了。

这套机制给我的安全感比闭源书架强太多。闭源书架的书源是它自己说了算，哪天某本书源被删了或者某本小说被下架了，你一点办法没有。Novella 把选择权完全交给用户，你信任哪个维护者就加哪个仓库，觉得不靠谱随时移除。当初我觉得麻烦，现在反而觉得这才是阅读器应该有的样子。

云同步：一个 Gist 解决了我所有换机焦虑

Novella 不用邮箱注册，它用 GitHub 账号登录。一开始我觉得这设计有点怪——一个阅读 App 为什么要绑 GitHub？后来才明白，它的云同步整个就是基于 GitHub Gist 做的。

登录流程走标准的 OAuth 2.0，它只请求两个权限：读取公开资料和 Gist 读写。授权后你随时可以在 GitHub 设置里撤回。我去年换手机的时候，就是在新设备上重新登了一下 GitHub 账号，书架、阅读进度、甚至书签都完整同步过来了。整个过程不到一分钟。

Novella 不会拿我的 GitHub 密码，也不会请求仓库读写或组织管理这些敏感权限。我平时用 GitHub 也不用担心，Gist 同步数据是私有的，别人看不到。这套设计虽然不那么"大众友好"，但对我这种本来就有 GitHub 账号的人来说，是最干净的同步方案——不用记住又一个账号密码，不用给任何平台存储邮箱。

不过话说回来，要是你没有 GitHub 账号或者不想授权，Novella 的本地书架完全不受影响，只是没有云同步而已。这点我觉得它做得挺克制的，不像有些 App 强迫你登录才能用核心功能。

书架更新：那些当初没注意的细节

书架更新这块是我后来越用越依赖的部分。Novella 的书架刷新是并发请求——不是一本书检查完再检查下一本，而是同时发出去。我书架上现在有三十多本书，下拉刷新一次完整检查大概三五秒就完成了。之前用的那款闭源阅读器，同样的书架规模刷新要等十几秒，而且经常卡着不动。

自动更新的调度也让我挺惊喜。设置里可以选更新频率、时间窗口、是否仅 Wi-Fi。我设的是每天凌晨两点只在 Wi-Fi 下更新。Novella 用的是 Android 的 WorkManager 调度后台任务，系统会把更新检查约束在允许的时间窗口内——比如待机充电的时候。实测下来耗电完全可以忽略，八个月了没因为这个掉电异常过。

当然也不是没踩过坑。有段时间我发现某本书在其他平台都更新了好几天了，Novella 里还是没反应。排查下来是四个原因：书源脚本本身很久没更新了、当前书源选了个滞后的来源、书架级批量刷新被书源端限速跳过了、或者书源直接挂了。Novella 在书籍详情页有个单本书下拉刷新的功能，强制让这个书源 API 返回最新列表，这招解决了大半问题。书源真挂了就只能换一个，或者去插件仓库的 Issue 区反馈维护者。

那些慢慢暴露的问题

说点不那么好听的。安装包从下载拿没问题，但 Android 的未知来源拦截是每次装 APK 都要面对的——点开 APK，系统弹出禁止安装未知来源，得点"设置"去给浏览器放行。国行机型更麻烦，小米有纯净模式要临时关一下，OPPO、vivo、华为还有安装守护安全检测，Novella 因为不是大厂出品可能会报"风险"，得手动点"仍要安装"。这些都是系统级的安全提示，不是 Novella 本身有问题，但每次装确实有点烦。

还有一个我没想到的问题是书源的维护稳定性。社区推荐的 LNReader 官方仓库更新最及时，第三方仓库就不一定了。我加的某个小仓库维护者大概半年没更过，有几个书源脚本还是老版本，适配不了目标网站的新结构。后来干脆把它移除了，换了另一个还在活跃维护的仓库。这就是开源生态的现实——每个用户自己判断信任度，自己承担选择的后果。

八个月后的观感修正

说实话刚开始用 Novella 的时候，我对它的预期是一个轻量级的阅读工具，能打开文件、能搜书就行。但八个月用下来，我发现自己当初低估了它几个设计：

Gist 云同步 我一开始觉得是个花哨功能，实际换机的时候才发现，能一键把三十多本书的进度和书签同步过来，比手动备份恢复强太多。

WorkManager 调度的自动更新 我一开始设了个 30 分钟的频率，后来改成每天凌晨，担心会不会漏更新。实际下来完全没必要——WorkManager 会把任务安排在系统空闲的时候，而且 Novella 有未读章节的角标提醒，真漏掉了手动下拉一下也很快。

插件仓库的安全设计 我一开始觉得麻烦，现在觉得这是它最有价值的特点。闭源书架的书源被删被改你完全没主动权，Novella 把这个权力还给了用户。

会不会卸载

八个月了，我没有卸载 Novella 的打算。它不是完美的——安装流程对国行机型不够友好，书源维护靠社区自觉，同步只绑定 GitHub。但它也没有让我动过换回去的念头：Gist 同步解决了换机焦虑，并发刷新和 WorkManager 调度让书架更新这件事几乎不占时间，插件仓库机制给了我闭源书架给不了的控制权。

什么信号出现我会考虑换？可能是某一天 LNReader 官方仓库也停更了，或者我书架上的主力书源集体失效。但在那之前，睡前刷两页书的习惯已经跟这个 App 绑在一起了。
