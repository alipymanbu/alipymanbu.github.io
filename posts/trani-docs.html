我在 TrAni 里摸到了手机上的 Navier-Stokes——这个壁纸 App 的技术底裤

下载官网 2026-10-16 ·约 9 分钟 ·老杨

从 TrAni 的流体模拟壁纸切入，拆解它如何用近似算法在移动端实现真实流体效果、为何选择 Android 开放接口而非 root 改系统、以及这种"够用就行"的设计思路背后的技术取舍与适用边界。

一个不像壁纸 App 的行为

我第一次在 TrAni 里点进"流体模拟"模板时愣了好一会儿。手指划过屏幕，画面里的液体会跟着旋转、汇流，甚至会在角落形成小旋涡——这效果我只在 PC 端的桌面演示程序里见过，没想到一个主打壁纸和图标的 Android app，居然敢在手机上算流体力学。

这不是一个"选张图片当壁纸"就能解决的事。流体模拟要解 Navier-Stokes 偏微分方程组，精确解算需要 GPU 集群跑好几个小时。TrAni 当然做不到精确解，但它让我意识到一件事：好的移动应用从来不追求"精确"，只追求"够用"——而这个"够用"的边界在哪，就是它的技术选型要解决的核心问题。

这篇文章我想拆三个问题：TrAni 怎么在手机上跑出能看的流体效果？它为什么放着"直接改系统图标"的捷径不走，非要绕一圈用 Android 的开放接口？以及，它的自动换壁纸为什么会被系统"吃掉"？想体验这些功能的话，直接去官网就能拿到最新版本。

流体模拟：在 CPU 上近似 Navier-Stokes

先看最硬核的部分。Navier-Stokes 方程描述的是流体的运动规律——密度、速度、压力随时间和空间的变化。精确求解是不可能的，但 TrAni 做了两个关键的近似：

离散化。把屏幕上的画面切成一个二维网格，每个格子存一个速度向量，流体的"流动"就是速度向量在相邻格子之间传递。这就把连续的偏微分方程变成了离散的线性运算，手机的 CPU 能扛住。

简化边界条件。真实流体有无数种边界——容器形状、障碍物、温度梯度。TrAni 只处理最简单的情况：手指划过 = 施加速度外力，屏幕边缘 = 固定不动。这样方程组就简化成了 4 个线性方程，可以用 Gauss-Seidel 迭代法几步解完。

样本文档里给了一个 FPS 对比表：水波纹空闲 60 FPS 触摸也 60，雨滴下落空闲 55 触摸 50，而流体模拟空闲就只有 45 FPS，触摸时掉到 30。官方建议骁龙 855 以上机型开启——骁龙 855 是 2018 年的旗舰芯片，5 年后 TrAni 还在用它当门槛，说明这套算法几乎没做硬件加速。

这其实是一个挺有意思的选择。如果 TrAni 把流体模拟搬到 GPU 上跑 OpenGL 计算着色器，帧率至少能翻倍，老机型也能开启。但代价是——GPU 计算着色器在不同厂商的 ROM 上表现差异极大，有的厂商会在省电模式下强制降频 GPU。用 CPU 算虽然慢一点，但在所有 Android 设备上行为一致，这对一个面向"全机型"的桌面美化工具来说，比极致性能更重要。

图标替换：绕开 root 的"后门接口"

TrAni 内置了十余套图标包——线性简约、圆角拟物、手绘风、像素复古、渐变霓虹。对很多用户来说，这是它比其他壁纸 App 更有吸引力的地方。但图标替换这件事，技术上有两条完全不同的路：

路 1：root 之后直接改系统图标。拿到 root 权限，替换系统目录里的 icon 文件，一行命令搞定，效果完美。但代价是——root 会触发 SafetyNet 检测，银行 App 和支付 App 全部打不开；而且大多数厂商的 bootloader 解锁都要申请，不对外开放。这条路能覆盖的用户不到 10%。

路 2：用 Android 的 Adaptive Icon 接口。Android 8.0 引入了 Adaptive Icon 机制，允许 launcher（桌面启动器）通过 ContentProvider 请求应用的图标资源。TrAni 做的是：把自己的图标包挂载成一个 ContentProvider，然后让 launcher 优先从 TrAni 取图标而不是从原应用取。

这条路的好处是完全不用 root，任何 Android 8.0+ 的设备都能跑，直接从下载拿安装包就能用。坏处也很明显——只有声明了 Adaptive Icon 的应用才支持替换，老应用（比如一些工具类 app）可能仍然用传统的静态图标，TrAni 拿不到它们的资源，只能跳过。样本文档里提到"部分老应用可能不支持图标替换"，这句话翻译一下就是：你能看到多少图标被美化，不取决于 TrAni 做得好不好，取决于那些被美化的 app 愿不愿意配合。TrAni 在这件事上没有话语权，这是 Android 生态的结构性限制，不是它的 bug。

自动换壁纸：为什么会被系统"吃掉"

自动换壁纸是 TrAni 最实用也最让人抓狂的功能。样本文档里列了它的配置项：30 分钟到 24 小时的间隔可选、可以同时换锁屏、随机或按收藏顺序、来源可以是收藏夹或每日推荐。但几乎每个用户都会碰到一个问题——换了几天之后它就停了，必须手动打开 TrAni 才能恢复。

原因不在 TrAni，在 Android 本身。Android 从 8.0 开始引入了后台执行限制，禁止普通应用在后台随意开服务。Doze 模式会在屏幕熄灭后一段时间让所有非活跃应用进入"沉睡"状态——网络访问被切断、后台服务被杀、定时器被延迟到下一次 Doze 唤醒窗口。厂商 ROM 更狠，小米的 MIUI 有"省电策略"默认就是"智能限制"，华为的 EMUI 白名单以外的应用后台存活率接近 0。TrAni 作为一个壁纸 App，在系统眼里优先级极低，Doze 和厂商策略会第一时间把它挂起。

TrAni 的解法其实没什么"技术含量"——它提示用户手动把自己加到电池白名单里，或者关闭"智能省电"。这不是 TrAni 偷懒，而是 Android 不给它别的选择：JobScheduler 有最小 15 分钟的调度精度，AlarmManager 的精确闹钟在 Android 12 之后也被限制了，前台服务需要通知常驻……一个想低调工作的壁纸 App，在 Android 的后台限制面前没有优雅的解法。解决这些后台问题、了解更多参数调优，都可以去看trani文档。

表情包走系统相册：同样是"最大公因数"思路

样本里还有一个细节我很在意：TrAni 的表情包下载后保存到相册或专属目录，然后在微信里手动添加。它不直接对接微信的表情面板。

为什么？因为微信没有开放"添加自定义表情"的 API。TrAni 如果想直接把表情塞进微信面板，要么走无障碍服务模拟用户操作（容易被系统拦截），要么反向破解微信的本地数据库（法律风险）。两种都不是一个正规应用能做的。

所以 TrAni 选了第三条路：走系统相册中转。相册是所有 Android 应用都能访问的公共空间，微信也认。这个方案笨但稳——用户多了一步操作，但 TrAni 没有任何合规风险，也不会因为微信版本更新而突然失效。

总结：够用就行的哲学

拆到这里，TrAni 的技术选型逻辑就很清晰了：

  • 用 CPU 近似 Navier-Stokes，不用 GPU 着色器 → 牺牲极致性能，换全机型兼容
  • 用 Adaptive Icon 接口，不用 root → 牺牲部分老应用覆盖，换零门槛安装
  • 提示用户加电池白名单，不用黑科技保活 → 牺牲用户体验，换合规安全
  • 表情包走相册中转，不硬对接微信 → 牺牲操作便捷性，换稳定可靠

这套哲学的本质是在 Android 生态的"最大公因数"上做文章。Android 碎片化严重，不同厂商的 ROM 差异巨大，而 TrAni 的目标用户是"普通 Android 用户"——他们可能用小米、华为、OPPO、三星，也可能用不知名的小众品牌。TrAni 不能假设用户的设备满足某个硬件条件或某个系统版本，所以它只能在最基础、最开放的接口上构建自己的功能。

这个思路的好处很明显：TrAni 能在超过 95% 的 Android 设备上安装并运行核心功能。坏处也同样明显——流体模拟的 FPS 上不去、部分老应用图标换不了、自动换壁纸偶尔罢工、表情包不能一键发送。它永远做不到"极致"，但对大多数用户来说，"够用"就已经够了。

这套资料在三个仓库都同步了——GitHub 是主维护线，Gitee 适合国内直连，GitCode 作为备份镜像。

如果 TrAni 有一天能让我在骁龙 660 上也跑出 60 FPS 的流体模拟，或者能直接一键把表情发到微信，那说明 Android 生态变好了——开放了新的接口，或者厂商的 ROM 更统一了。在那之前，TrAni 保持这种"够用就行"的设计哲学，反而是最务实的选择。
