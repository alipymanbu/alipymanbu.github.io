把 AI 伙伴嵌进自媒体工作流：用 AIRI 省下每天三小时的碎片化切换

正版 2026-10-16 ·约 7 分钟 ·老杨

一个把 AIRI 当内容生产中枢的完整流程——从资料检索到大纲整理到配图描述，以前三步切五个窗口，现在托盘快捷键一键直达，关键环节不缩水。

我每周要做两件事：给公众号写 1~2 篇科技类长文，给视频平台剪一条三分钟资讯短片。以前这条线要五个应用来回切——浏览器搜资料、笔记软件列大纲、IDE 存素材、绘图工具跑 prompt、邮箱发定稿。不是哪个软件不好用，是每一次切换都要找回上下文，查资料查到一半要记个待办、写大纲时想补个配图描述、出片前要核对最新数据，心智流被打断的次数比我愿意承认的多得多。

直到去年年底把 AIRI官网 这款开源 AI 伙伴插进了这条链。现在的流程是：托盘快捷键唤起快速操作浮窗一句话触发搜索，她从 Tavily 拉最新资料自动整理要点，聊天窗口里把这些要点揉成大纲，再让她给每个段落配好绘图描述——全程窗口只开一个，需要什么直接说，结果要么塞进草稿要么进系统通知。

旧流程卡在哪

说清楚痛点才能理解 AIRI 为什么解决问题。以前这条链的四个断点：

  1. 资料检索与写作割裂：浏览器查完一堆标签页，得手动复制粘贴到笔记软件，粘完还要删广告、去重、调格式——一次整理半小时起。
  2. 配图描述是额外工序：大纲写完开绘图工具，对着每一段想 prompt，写了一堆复制过去跑图，结果不对又回来改 prompt。
  3. 碎片指令无处落脚：写着大纲突然想起一个待办，得开待办软件记一笔；想查一个新版本号，得重新开浏览器搜。
  4. 晚上不想干活但有收尾要做：白天查的资料晚上才有空整理，但这会儿不想开一堆窗口。

这四个断点加起来，每篇文章至少多出一小时的"来回搬运"时间。

新流程：把 AIRI 放中枢位

核心思路是：把所有"一句话就能搞定的请求"都塞给 AIRI，让她当我的工作流路由器——只有涉及长篇写作和最终定稿时才跳去专门的工具。

上下游工具长什么样

AIRI 不替代任何专业工具，她在专业工具之间接碎片：

  • 前接 Tavily 网络搜索：让她能查实时数据（新闻、版本号、价格），这是她相对本地 AI 的最大优势
  • 中联写作助手：把检索到的资料整理成大纲，给每个段落配绘图描述
  • 后接笔记软件与绘图工具：整理好的大纲我复制进笔记工具排版，配好的 prompt 直接丢给绘图工具跑图
  • 系统通知兜底：快速操作的结果（一句话指令的返回）走系统通知，不用开聊天窗口等

整下来窗口常驻只有两个：笔记软件 + AIRI 托盘，绘图工具和浏览器只在出图和定稿排版时短暂打开。

具体怎么接入

搜索模块的配置是这套流程最关键的一步——没配好，AIRI 就是个只会说已有知识的聊天工具，嵌不进任何需要实时信息的工作流。按文档给的四步：

  1. 去 Tavily 控制台注册拿 API Key（有免费额度，够用起步）
  2. 打开 AIRI「设置 → 机体模块 → 网络搜索」
  3. 开关打开、密钥粘贴进去
  4. 看到"网络搜索已就绪"就完成了

有一个前提容易被忽略：聊天模型必须支持工具调用，否则她不会主动发起搜索。AIRI 的意识模块支持换模型，如果用了一个阉割版模型，搜索按钮亮着但实际不搜，排这一条就对了。

搜索配好之后，托盘右键菜单里的"打开快速操作"就成了高频入口。我把她的全局快捷键改成了 Ctrl + Alt + A（Spotlight 风格的召唤，任何应用里直接按），触发后弹一行输入框，输完指令回车她自动隐藏，结果以系统通知形式飘上来——比如我在写大纲时想让她"搜索一下今天 AI 圈有什么值得写的新闻，列三条要点"，就这一行字，回车后继续写我的大纲，通知到了直接点开看。

两个容易断链的环节

说这套流程能跑起来容易，实际用了两三个月，有两个环节出过问题。

搜索配好了但她不搜

头一周遇到好几次——明明说"搜索 XXX"，她直接用已有知识回答了。排查下来是三个原因：开关不小心关了（托盘菜单里快速切换容易碰着）、模型不支持工具调用（换了一个便宜模型忘了查）、提问没给明确指令。最后一个是心智问题：你说"帮我看看 AI 圈最近有什么新闻"，模型可能判断"已有知识够用"就不搜——得把指令说死："搜索今天 AI 圈的新闻，列三条要点，附上每条的来源链接"。

费用怎么控制

AIRI下载 本身免费，MIT 开源，但背后跑的模型和搜索服务是花钱的。初期先用了官方提供商的 150 电量免费额度，确实够摸清自己的使用频率。正式用的时候切到了国产模型服务（人民币计费 + 国内网络友好），配合本地 TTS（Kokoro），单篇文章的搜索 + 对话成本不超过五毛。如果愿意折腾，Ollama 本地模型配合本地语音，整套能做到零成本——当然代价是要一张够劲的显卡。

效果和边界

量化一下实际省了多少事：每篇文章的"碎片搬运"时间从一小时降到了二十分钟以内——少了两次浏览器笔记软件的来回复制，少了在绘图工具里反复调 prompt 的回合，待办随手一句话就记了。

但这套流程不是万能的，说清楚边界免得踩坑：

  • 不适合做最终定稿：AIRI 整理的大纲和绘图描述需要人过一遍，她给的搜索结果也需要点开来源核实——模型会有偏见、搜索会过时，别直接信。
  • 不适合全离线：搜索依赖 Tavily，模型服务也需要网络；如果要断网用，得提前配好本地模型，效果和成本是另一套账。
  • 不适合非常复杂的多步骤任务：她适合一句话指令、适合整理和辅助，真要做一篇深度分析，还是得自己在专业工具里写。

说到底，AIRI 在这套流程里的角色不是"替你干活的 AI"，是"帮你把碎片接起来的路由器"——把你本来要在五个应用之间跑来跑去的那些小动作，集中到一个托盘快捷键里。这种用法放在任何需要频繁查资料、整理信息、配配图的工作流里都成立，不止自媒体。顺手说一句，这套资料分别传到了 GitHub、Gitee 和 GitCode，国内外节点各一份免得访问受限。
